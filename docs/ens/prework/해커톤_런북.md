### T+60 → T+90

- **ENS:** 기본 레코드를 `capPerFill = 0`으로 넣고, MM 이름 두 개 + 만료 데모용 한 개 발급. `addr`과 `desk.terms` 기록
- **Aqua:** 명령어 #34(ENS 게이트)를 먼저 쓴다. 가격(#35)보다 먼저다 — 게이트가 ENS 트랙의 핵심이고, 가격은 나중에 고정값으로도 데모가 돌아간다
- **Web:** `readClient` 붙여서 실제 ENS 값 표시로 교체

### 순서가 이런 이유

- `desk.eth` 등록은 commit 후 60초를 기다려야 하므로 **제일 먼저 걸고 다른 일을 한다.** 단 commit은 24시간 뒤 만료되고(`MAX_COMMITMENT_AGE` 86,400초), 최소 등록 기간은 28일이다.
- 게이트를 가격보다 먼저 쓰는 이유는 두 트랙 중 ENS 쪽이 더 확실하고, 게이트가 돌아가면 데모 1·3번이 바로 나오기 때문이다.
- 리스크 에이전트 자동화는 마지막이다. 체결 경로가 에이전트를 부르지 않으므로, 데모 4번은 사람이 에이전트 키로 `setData`를 한 번 누르는 것으로도 성립한다.

## 인터페이스 계약

세 파트가 같은 바이트를 써야 하는 지점이다. **여기가 어긋나면 통합 지점에서 반나절을 날린다.** 시작 전에 이 절만 구두로 맞춘다.

### 레코드 인코딩 (비대칭 반영)

```solidity
// desk.terms  — 멀티시그만 쓴다
abi.encode(uint8 version, uint16 askBps, uint16 bidBps, uint128 capPerFill)

// desk.spread — 리스크 에이전트만 쓴다
abi.encode(uint8 version, uint16 askBps, uint16 bidBps, uint64 validUntil)
```

- `version = 1`. 라우터는 모르는 버전이면 revert한다.
- ask는 데스크가 ETH를 파는 쪽, bid는 사는 쪽이다. **bid를 더 넓게** 준다.
- `desk.spread`가 비었거나 `validUntil`이 지났으면 `desk.terms`의 등급 값으로 돌아간다. 그 등급 값은 **보수적으로 넓게** 잡는다. 좁으면 에이전트를 멈추는 게 공격자에게 이득이 된다.
- 최종 스프레드는 전략의 `[minBps, maxBps]`로 clamp한다. `minBps`는 피드 편차 밴드 이상(실측 약 50bps).

### 이름 전달

- MM은 `swap` 호출 시 `takerData`에 **DNS 인코딩된 전체 이름**을 넣는다.
- taker는 라우터가 기록하는 `msg.sender`다. 이름에서 주소를 역으로 찾지 않는다.
- ENS 담당의 `encodeTakerName()`과 라우터의 파싱은 **같은 바이트를 내야 한다.** T+0에 예제 한 개를 서로 교환해 먼저 맞춘다.

### 체결 이벤트

```solidity
event DeskFill(
    bytes32 indexed nameHash,   // 이름 해시 (에이전트가 MM별로 묶는 키)
    address indexed taker,
    address tokenIn, address tokenOut,
    uint256 amountIn, uint256 amountOut,
    uint256 mid,                // 사용한 오라클 중간값
    uint16  appliedBps,         // 적용된 스프레드
    uint64  weightBefore        // 체결 직전 ETH 비중 (1e18 기준)
);
```

호가 조회 중에는 이벤트를 남기지 않는다. `isStaticContext`가 false일 때만 남긴다. 이 이벤트가 리스크 에이전트와 웹 앱의 유일한 입력이다.

### 실패 이름

데모에서 화면에 띄울 이름이라 미리 고정한다.

| 이름 | 언제 |
| --- | --- |
| `NotWhitelisted` | 이름이 없거나 인코딩 불일치 |
| `NameExpired` | 이름 또는 상위 이름이 만료 |
| `WrongResolver` | resolver가 트레저리 resolver가 아님 |
| `TakerMismatch` | `addr` ≠ `msg.sender` |
| `CapExceeded` | 수량이 `capPerFill` 초과 |
| `StaleOracle` | 오라클 갱신이 허용치 초과 |

### 웹 앱이 받는 함수

ENS 담당이 제공한다. 시그니처만 먼저 확정하고 구현은 T+15 이후에 한다.

```ts
readClient(name) → { addr, askBps, bidBps, capPerFill, spreadAsk, spreadBid, validUntil, expiry, resolverOk }
addClient(label, addr, askBps, bidBps, capPerFill, expiry)
setSpread(name, askBps, bidBps, validUntil)
encodeTakerName(name) → bytes
```

## 체크포인트와 대안

시간은 해킹 시작을 T+0으로 본 상대 시간이다. 각 지점에서 **된다인지 안 된다인지만 판단하고, 안 되면 그 자리에서 갈아끼운다.** 미루다 시간을 잃는 것이 제일 큰 위험이다.

| 시점 | 판단할 것 | 안 되면 |
| --- | --- | --- |
| T+2 | 1inch 부스가 Sepolia 제출을 인정하는가 | ENS 레코드를 라우터 스토리지에 미러링하고 지원 체인으로 옮긴다. ENS 논거가 약해지므로 마지막 수단 |
| T+2 | `desk.eth` 등록 성공 | 대체 이름(otcdesk, quotedesk 등)으로 바로 갈아탄다 |
| T+4 | 이름이 resolve되고 `desk.terms` 디코딩이 된다 | 서브레지스트리가 막히면 `desk.eth` 하나에 MM별 키를 여러 개 두는 구조로 낮춘다 |
| T+8 | 라우터가 ENS 게이트를 통과·거절한다 | 체결 안 ENS 읽기가 가스로 막히면 `desk.terms`를 전략 바이트로 옮기고 ENS에서는 게이트와 `desk.spread`만 읽는다 |
| T+12 | 실제 fill 1건이 온체인으로 성공한다 | 우리 지갑 둘로 maker와 taker를 모두 운영하는 통제된 데모로 전환하고, 심사 때 조건을 먼저 밝힌다 |
| T+14 | 이름 → 화면 → 체결까지 한 번 관통된다 | 가격을 고정값으로 낮추고 게이트만 살린다 |
| T+24 | 해피 패스 고정 | 이후 새 기능은 어떤 스폰서 트랙도 추가하지 않는다 |
| T+30 | 녹화본 완성 | 라이브 데모가 터져도 제출할 것이 있어야 한다 |

### 버리는 순서

시간이 모자라면 이 순서로 지운다. 앞에 있는 것부터 버린다.

1. 리스크 에이전트 자동화 (사람이 `setData` 한 번 누르면 데모 4번은 성립)
2. `desk.stats` 레코드와 markout 계산
3. 재고 스큐 계수 κ 튜닝 (데모 수치만 맞으면 된다)
4. Curvegrid · World 트랙
5. 웹 앱의 꾸밈

반대로 **절대 버리지 않는 것**은 세 개다. ENS 게이트 네 확인, 온체인 fill 1건, 그리고 만료된 이름이 거절되는 장면. 이 셋이 두 트랙의 심사 근거다.

## 데모 시드값과 제출

### 시드값 (그대로 넣으면 된다)

직접 계산해서 화면에 변화가 보이는 값으로 골랐다.

| 항목 | 값 |
| --- | --- |
| 트레저리 재고 | 60 WETH + 60,000 USDC (비중 80%) |
| 목표 비중 | 70% |
| κ (재고 스큐 계수) | 0.02 |
| 오라클 시작가 | 4,000 |
| mm-a | ask 10bps / bid 25bps, capPerFill 5 WETH |
| mm-b | ask 25bps / bid 50bps, capPerFill 5 WETH |
| mm-c (만료 데모용) | mm-a와 같은 조건, 만료를 짧게 |
| 전략 clamp | minBps 50 / maxBps 300 |

이 값이면 체결 한 건당 호가가 **13.3bps(약 5.3달러)** 움직이고, 세 번이면 40bps(16달러)다. 팀 문서 예시(900 ETH, cap 10)는 건당 2bps라 화면에서 안 보인다.

`minBps 50`은 피드 편차 밴드 이상으로 둔 값이다. 데모에서 mm-a의 10bps는 clamp에 걸려 50bps로 올라간다 — **이건 버그가 아니라 설계다.** 발표에서 이 장면을 근거로 쓴다.

### 데모 네 장면

1. mm-a와 mm-b가 같은 5 WETH를 요청해 다른 가격을 받는다. 명단 밖 주소는 `NotWhitelisted`
2. 같은 방향으로 세 번 체결하면 호가가 40bps 불리해진다
3. mm-c의 이름이 만료되자 다음 체결이 `NameExpired`
4. 에이전트가 mm-a의 스프레드를 넓히고, 같은 키로 `addr`을 바꾸려하면 `EACUnauthorizedAccountRoles`

장면 2와 4는 오라클과 레코드를 손으로 움직여야 하므로 **순서와 값을 적어두고 그대로 재생**한다. 두 번째 화면에 이벤트 로그를 띄워두면 심사위원이 따라오기 쉽다.
